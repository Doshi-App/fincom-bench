| all | `datasets/meta-eval.csv` | The `labeller_a_label` column was **not a human label**. Its 274 values were identical, row for row, to a candidate judge's output (the column exported elsewhere as `kimi_k2_7_code`). The cause was the header rename recorded in `lib/datasets.ts`: `human_label` was split into `labeller_a_label`/`labeller_b_label`/`notes` without regenerating the row data, so the column names moved and the values did not. Against the 100 rows a person has since labelled by hand, `labeller_a_label` agreed on only 77. `labeller_b_label` was empty. **Fixed:** `labeller_a_label`, `labeller_b_label`, and 12 empty candidate-judge columns (`gpt_5_6_sol` … `glm_4_5`) are dropped from `meta-eval.csv`. Judge selection uses the hand-labelled file instead (`harness/pipeline/human-labels.csv`). That file is not published, and judge selection cannot be independently verified from this repository — see `results/README.md`. | Overnight judge-selection run; columns dropped before public release | 2026-08-13 |
